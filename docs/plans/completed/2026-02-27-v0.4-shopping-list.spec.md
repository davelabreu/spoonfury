# Spoonfury v0.4 — Shopping List, Buy it NOW!, Cook Now & NavBar Theme Toggle

**Date**: 2026-02-27
**Status**: Approved

---

## Overview

Four features shipped as one cohesive v0.4 release:

1. **Shopping List** — server-side, syncs across devices. Aggregates ingredients from multiple recipes into a meal-plan-driven shopping list.
2. **Buy it NOW!** — immediate Instacart purchase with pickup/delivery intent, usable from both RecipePage and ShoppingListPage.
3. **Cook Now mode** — Wake Lock API keeps the screen on while cooking.
4. **NavBar Theme Toggle** — switch between the original minimal animated-tabs style and the current fridge-sticker style.

---

## Feature 1: Shopping List

### Ingredient Checkbox Semantics (Breaking Change)

The meaning of the ingredient checkbox is **inverted** from v0.3:

| State | Meaning | Effect |
|-------|---------|--------|
| **Unchecked** | "I need to buy this" | Included in shopping list / Instacart |
| **Checked** | "I already have this" | Excluded |

Default state on load: **all unchecked** (assume you need everything).

This affects `IngredientChecklist.tsx`: initialise `checked` as an empty `Set`, and invert all conditional styles and filtering logic.

### Backend — New Django app: `shopping`

#### Models

```python
# shopping/models.py

class ShoppingList(models.Model):
    owner = models.OneToOneField(
        settings.AUTH_USER_MODEL,
        on_delete=models.CASCADE,
        related_name="shopping_list",
    )
    updated_at = models.DateTimeField(auto_now=True)


class ShoppingListItem(models.Model):
    shopping_list = models.ForeignKey(
        ShoppingList, on_delete=models.CASCADE, related_name="items"
    )
    recipe = models.ForeignKey(
        "recipes.Recipe",
        on_delete=models.SET_NULL,
        null=True,
        blank=True,
        related_name="+",
    )
    # Denormalized: survive recipe deletion, allow linking back
    recipe_title = models.CharField(max_length=100)
    recipe_slug = models.SlugField(max_length=120)

    # Copied from recipe ingredients at add time
    name = models.CharField(max_length=200)
    quantity = models.CharField(max_length=50, blank=True)
    unit = models.CharField(max_length=50, blank=True)
    note = models.CharField(max_length=200, blank=True)

    # "Picked up at the store" checkbox — separate from recipe-page checkbox
    is_checked = models.BooleanField(default=False)
    added_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        ordering = ["added_at"]
```

#### API Endpoints (all auth-required)

| Method | URL | Body | Purpose |
|--------|-----|------|---------|
| `GET` | `/api/shopping-list/` | — | Full list; items grouped by recipe in response |
| `POST` | `/api/shopping-list/add/` | `{ recipe_slug, recipe_title, ingredients: [{name, quantity, unit, note}] }` | Add batch from one recipe. Auto-creates ShoppingList if absent. Skips duplicates. |

| `DELETE` | `/api/shopping-list/items/{id}/` | — | Remove one item |
| `POST` | `/api/shopping-list/clear/` | — | Wipe all items |

## Feature 2: Buy it NOW! (Pickup or Delivery)

### Instacart URL Builder Fix

Replace the current single-query approach with **one search URL per ingredient**. Open as a sequence or open the first and let Instacart handle it. For now: open a single Instacart search URL with each ingredient as a separate line item using Instacart's `?term=` with items joined by `%0A` (newline), which produces better per-item matching than comma-separated.

```ts
// lib/instacart.ts
export function buildInstacartUrl(
  ingredients: Ingredient[],
  fulfillment: "pickup" | "delivery"
): string {
  if (ingredients.length === 0) return "https://www.instacart.com";
  const terms = ingredients
    .map(i => `${i.quantity} ${i.unit} ${i.name}`.trim().replace(/\s+/g, " "))
    .join("\n");
  // fulfillment param reserved for Instacart Shoppable Recipe API (post-v0.4)
  return `https://www.instacart.com/store/search_v3/term?term=${encodeURIComponent(terms)}`;
}
```

## Feature 3: Cook Now Mode

Purely frontend. No backend changes.

### Trigger

"Cook Now 🔥" button added to the action bar in `RecipePage`. Visible to all users (logged in or not).

### Implementation

```ts
// hooks/useWakeLock.ts
export function useWakeLock() {
  const [active, setActive] = useState(false);
  const lockRef = useRef<WakeLockSentinel | null>(null);

  const acquire = async () => {
    if (!("wakeLock" in navigator)) { setActive(true); return; } // graceful
    lockRef.current = await navigator.wakeLock.request("screen");
    setActive(true);
    lockRef.current.addEventListener("release", () => setActive(false));
  };

  const release = () => {
    lockRef.current?.release();
    lockRef.current = null;
    setActive(false);
  };

  useEffect(() => () => { lockRef.current?.release(); }, []);

  return { active, acquire, release, supported: "wakeLock" in navigator };
}
```

### Cook Now Banner

When active, a sticky banner renders between the NavBar and recipe content:

```
┌─────────────────────────────────────────────┐
│  🔥 Cooking mode  •  Screen will stay on    │
│                              [ Done cooking ]│
└─────────────────────────────────────────────┘
```

- Amber/warm background to signal active state
- "Done cooking" calls `release()` and dismisses
- If Wake Lock unsupported: banner shows with a note "Screen sleep prevention not supported on this browser" — the mode still activates visually

## Feature 4: NavBar Theme Toggle

### Storage

`localStorage` key: `"spoonfury-nav-theme"` — values `"minimal"` | `"sticker"` (default: `"sticker"`).

### Hook

```ts
// hooks/useNavTheme.ts
export function useNavTheme() {
  const [theme, setTheme] = useState<"minimal" | "sticker">(
    () => (localStorage.getItem("spoonfury-nav-theme") as any) ?? "sticker"
  );
  const toggle = () => setTheme(t => {
    const next = t === "sticker" ? "minimal" : "sticker";
    localStorage.setItem("spoonfury-nav-theme", next);
    return next;
  });
  return { theme, toggle };
}
```

### NavBar restructure

`NavBar.tsx` becomes a shell:

```tsx
export function NavBar() {
  const { theme, toggle } = useNavTheme();
  return theme === "sticker"
    ? <StickerNav onThemeToggle={toggle} />
    : <MinimalNav onThemeToggle={toggle} />;
}
```

- `StickerNav` — current NavBar implementation (extracted as-is)
- `MinimalNav` — restored from the v0.2 animated-header design: `layoutId="hoverBubble"` + `layoutId="activeUnderline"`, clean tabs, muted text

Theme toggle button: a small `✦` icon in the right column of both nav variants. On the sticker nav it's a NavSticker with `color="bg-white"`. On the minimal nav it's a ghost icon button.
